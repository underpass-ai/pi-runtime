# Aceptación F3 — fase `run` de MADE en la instalación real

Fecha: 2026-09-30. Máquina real del usuario, sin contenedores ni mocks del producto: una sesión real
de Pi por el SDK, el host real del proyecto y los binarios fijados de `kmp-mcp` y `made-mcp`. El
modelo es el proveedor `faux` de pi-ai (respuestas guionizadas, sin red), como en E1, O1, L1 y S3a:
el guion de la fase `run` decide cada paso leyendo la instancia que devuelve MADE (paso reclamable →
reclamar y completar; si no, la transición habilitada; `lifecycle: ended` → parar).

Versiones: pi-runtime `feat/f3-made-run-phase` (`80f5170`), Pi 0.87.1, Node v22.23.2, `kmp-mcp`
0.24.0, `made-mcp` 0.8.0.

## Cómo se montó

Como en S3a: un proyecto git desechable y el estado aislado en directorios temporales cortos (`0700`):

| Variable | Qué aísla |
|---|---|
| `XDG_STATE_HOME=<tmp>/state` | log de eventos, socket, spool y huellas de catálogo del proyecto |
| `MADE_MCP_STORE_PATH=<tmp>/state/underpass-made/ceremonies.sqlite3` | el store de MADE |
| `MADE_SETUP_CONFIG_ROOT=<tmp>/madecfg` | configuración privada de MADE para ese store |
| `KMP_MCP_DATA_DIR=<tmp>/kmp` | memoria de KMP: un store vacío |

Ni el store compartido de MADE (`~/.local/state/underpass-made/ceremonies.sqlite3`), ni su
configuración, ni `~/.pi/agent/settings.json` se tocaron. Comprobado después en sólo lectura: el
store compartido no contiene ni la definición `pi_runtime_run_smoke` ni la instancia
`pi-runtime-run-smoke-1`. No se borró nada de él.

1. Ningún host de pi-runtime abierto (`pgrep -af 'underpass-host[.]ts'` vacío; uno de otro proyecto
   que corría desde el checkout principal se esperó a que saliera solo por inactividad). El checkout
   principal estaba limpio en `main` (`e8a13e7`).
2. `git -C ~/Documents/ai/pi-runtime checkout --detach 80f5170`; todo (CLI y scripts) desde ese
   checkout.
3. `node tests/acceptance/made-config.ts`: `made config created`, `authorization bootstrap OK`.
4. Al terminar: el host del proyecto temporal parado por PID (sus `kmp-mcp` y `made-mcp` salieron
   con él), `git checkout main` (`e8a13e7`), `git status --short` vacío y el estado temporal borrado.

`host_callback`, `draft` y `review`); `/underpass-phase run`; arrancarla como
`pi-runtime-run-smoke-1` y llevarla al terminal; `/underpass-status`; cierre.

## Límites conocidos

- **Instrucciones de los pasos de una publicada ajena a la sesión.** Con `made-mcp` 0.8.0 ni la
  instancia, ni la reclamación, ni el transcript devuelven el `prompt` de un paso: el agente puede
  llevar al terminal una publicada como `pr_review_two_reviewers`, pero sin saber qué pide cada paso
  salvo que la haya diseñado en la sesión (como en esta aceptación). MADE 0.9.0 traerá
  `made_get_ceremony_definition`; cuando pi-runtime fije `made-mcp` 0.9.0 se añadirá a `run` como
  lectura (`auto`).
- **Terminal por fuera.** El terminal se detecta en los resultados: si otro cliente termina la
  instancia y la sesión no la vuelve a leer, sus grants viven hasta el cierre de la sesión (12 h como
  máximo).
